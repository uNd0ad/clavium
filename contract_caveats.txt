CONTRACT TEMPLATE CAVEATS — to revisit (written iul 2026, after merging Contract_inchiriere.docx
into config/contracts/inchiriere.md)

1. RETROACTIVE PDF REGENERATION
   Edits to config/contracts/*.md change the regenerated PDF of contracts that are ALREADY
   SIGNED, because the final signed PDF is not persisted separately yet (only regenerated from
   the template + contract data on demand). Before any post-launch template edit, ship the
   ROADMAP item "persist final signed contract PDF" (store the exact signed bytes in R2 at
   signing time; regeneration only as fallback). Until then, substantive template edits on
   production data are unsafe.

2. LEGAL SIGN-OFF (blocker before paid launch)
   The merged text (titlu executoriu, pact comisoriu, ANAF, certificat energetic, PAD, regim
   hotelier ban, art. 1825 preaviz) has NOT been reviewed by a lawyer. ROADMAP Phase 3 item.
   Same applies to config/contracts/vanzare.md.

3. ANNEXES NOT GENERATED (dropped from the docx merge by design)
   Contract_inchiriere.docx contains three annexes the platform does not produce:
     - Anexa 1: proces-verbal de predare-primire (keys, meter indexes, condition checklist)
     - Anexa 2: inventar bunuri (furniture/appliance table with condition + serials)
     - Anexa 3: regulile locuinței (smoking/pets/quiet-hours checkboxes)
   The template engine (contractTemplate.ts) only supports headings/paragraphs/sub-points —
   no tables or checkboxes. These need a separate generated-documents feature (own templates,
   own data model for meter readings + inventory, signed alongside the contract). The contract
   text already REFERENCES the proces-verbal as "parte integrantă", so generating it is the
   natural next step; until then owners must do it on paper.

4. DATA THE PLATFORM DOES NOT COLLECT (silently reworded in the merge)
   The docx expects: C.I. seria/nr., IBAN, Cartea Funciară / nr. cadastral, certificat
   energetic nr., cohabitant names/CNPs, max occupancy. The template now says these come from
   the header or "clauzele speciale". If we want them printed properly, add fields to the
   contract creation flow (owner side: CF/cadastral + energetic cert; tenant side: cohabitants).

5. DELIBERATE DEVIATIONS FROM THE DOCX (platform model — do not "fix" accidentally)
   - Payment exclusively via Clavium.ro (docx allowed cash + chitanță).
   - Tacita relocațiune EXCLUDED (docx allowed it per art. 1810); renewal only via platform.
   - Owner-side denunțare for personal housing needs (art. 1825 alin. 2) NOT included.
   - Party identification blanks removed — header injects CNP/address/email automatically.

6. HARD-CODED VALUES NOW IN THE TEMPLATE (were fill-in blanks in the docx)
   Penalties 0.1%/day capped at principal; reziliere after 30 days non-payment + 15-day pact
   comisoriu notice; garanție restituted in 30 days; access notice 24h; viewings in last 30
   days; force majeure: 5-day notification, denounceable after 30 days. If owners ask for
   configurability, these become contract-level fields ("clauze speciale" covers one-offs).
